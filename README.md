## Selected case studies

### 01. LinkUs · 지도 기반 지역 커뮤니티 `MVP Delivered`

**장소와 콘텐츠가 분리되어 발생하는 탐색 비용**을 줄이기 위해, 현재 위치를 첫 탐색 기준으로 두고 게시물·채팅·신고·운영이 지도 위에서 이어지도록 설계했습니다.

- 59개 요구사항을 `Requirement ID → Screen → Route → DB/API → Acceptance`로 추적
- Guest / Member / Admin 상태 기반 IA와 Map Post·Location Chat·Report 흐름 정의
- Initial·Empty·Loaded·Submitting·Failed·Forbidden 상태와 복구 정책 설계
- 인증·게시물·채팅·신뢰·관리자 영역의 5개 핵심 QA 시나리오 검증
- 공식 Front 역할에서 기획 문서·기능 정책·통합 QA까지 기여 범위 확장

### 02. Questlog · 회복 중심 AI 루틴 서비스 `In Progress`

연속 기록보다 **실패 후 48시간 안에 다시 돌아오는 경험**을 우선합니다. AI는 목표 분해와 제안을 담당하고, 보상·상태·권한은 예측 가능한 규칙과 서버가 결정하도록 책임을 분리하고 있습니다.

- 목표 → Chapter → Quest → Check-in → Review의 핵심 루프 설계
- 회복 상태·복귀 안내·캐릭터 피드백 정책 정의
- 반응형·키보드·ARIA·reduced-motion 회귀 기준 수립
- 완료되지 않은 기능과 성과는 완료처럼 표시하지 않음

## My planning standard

```text
기획 완료 ≠ 문서 작성 완료
기획 완료 = 팀이 같은 기준으로 구현하고 검증할 수 있는 상태
```

- 요구사항에는 화면뿐 아니라 권한·데이터·API·수용 기준을 연결합니다.
- 정상 경로와 함께 Empty·Loading·Failed·Forbidden·Recovery를 정의합니다.
- 결정에는 대안, 선택 이유, 영향 범위, 확인 근거를 남깁니다.
- 측정하지 않은 수치는 성과처럼 말하지 않고 다음 검증 계획으로 분리합니다.
